# Spring REST Docs

## 배경

API 명세를 별도 문서로 관리하면 구현이 변경될 때마다 문서를 함께 수정해야 한다.  
이 과정이 누락되면 문서와 실제 동작이 어긋나고, 시간이 지나면 문서를 신뢰할 수 없게 된다.

[05. API 명세](05.ApiDocument.md)는 요청·응답 구조를 직접 작성한 문서이므로 이 문제에 노출되어 있다.  
따라서 **테스트 코드로부터 API 문서를 생성하는 방식**을 도입하여, 문서와 구현의 정합성을 빌드 단계에서 보장하도록 하였다.

Spring REST Docs는 컨트롤러 테스트가 실제로 수행한 요청과 응답을 스니펫으로 출력한다.  
테스트가 실패하면 스니펫이 생성되지 않으므로, **문서가 생성되었다는 사실 자체가 해당 API가 동작한다는 근거**가 된다.

Swagger(OpenAPI)와 비교하면 다음과 같은 차이가 있다.

| 항목         | Spring REST Docs  | Swagger (springdoc)  |
|------------|-------------------|----------------------|
| 문서 생성 근거   | 테스트 실행 결과         | 프로덕션 코드의 애노테이션       |
| 구현과의 정합성   | 테스트 실패 시 문서 생성 중단 | 애노테이션 갱신 누락 시 불일치 발생 |
| 프로덕션 코드 침투 | 없음                | 애노테이션이 컨트롤러에 추가됨     |
| 테스트 요구     | 문서화하려면 테스트 작성이 필요 | 불필요                  |
| API 호출 기능  | 없음 (정적 문서)        | 제공 (Try it out)      |

프로덕션 코드를 오염시키지 않고 문서 신뢰성을 확보하는 것이 목적이므로 Spring REST Docs를 선택하였다.

## 문서화 대상

MSA로 분리된 6개 서비스 중, 외부에 공개되는 API를 보유한 4개 서비스를 문서화 대상으로 지정하였다.

| 서비스     | API           | 스니펫 식별자        |
|---------|---------------|----------------|
| balance | 잔액 조회         | balance-get    |
| balance | 잔액 충전         | balance-charge |
| coupon  | 보유 쿠폰 목록 조회   | coupon-list    |
| coupon  | 쿠폰 발급         | coupon-issue   |
| order   | 주문 생성         | order-create   |
| product | 상품 목록 조회      | product-list   |
| product | 인기 상품 Top5 조회 | product-ranks  |

payment와 user 서비스는 서비스 간 내부 통신 및 이벤트 처리만 담당하므로 문서화 대상에서 제외하였다.

## 공통 테스트 지원

`support:rest-docs` 모듈에 문서화 설정을 공통화하여, 각 서비스가 동일한 방식으로 스니펫을 생성하도록 하였다.

```java
@ExtendWith(RestDocumentationExtension.class)
public abstract class RestDocsSupport {

    protected MockMvc mockMvc;

    @BeforeEach
    void setUpRestDocs(WebApplicationContext context, RestDocumentationContextProvider provider) {
        this.mockMvc = MockMvcBuilders.webAppContextSetup(context)
                .apply(documentationConfiguration(provider)
                        .operationPreprocessors()
                        .withRequestDefaults(prettyPrint())
                        .withResponseDefaults(prettyPrint()))
                .build();
    }
}
```

`webAppContextSetup`을 사용한 이유는 기존 컨트롤러 테스트가 `@WebMvcTest` 기반이기 때문이다.  
`standaloneSetup`으로 구성하면 컨트롤러를 직접 생성하므로 예외 처리기(`ApiControllerAdvice`)와 메시지 컨버터 설정이 적용되지 않아,  
문서에 기록되는 응답이 실제 애플리케이션의 응답과 달라진다.

각 서비스의 `ControllerTestSupport`는 이 클래스를 상속하고 서비스별 목(mock)만 선언한다.

```java
@WebMvcTest(controllers = {
        BalanceController.class,
})
public abstract class ControllerTestSupport extends RestDocsSupport {

    @Autowired
    protected ObjectMapper objectMapper;

    @MockitoBean
    protected BalanceFacade balanceFacade;
}
```

## 문서화 작성 방식

기존 컨트롤러 테스트의 검증 구문에 `document()`를 추가하는 형태로 작성하였다.  
별도의 문서화 전용 테스트를 만들지 않았으므로, **테스트가 늘어나지 않고 문서만 추가된다.**

```java
mockMvc.perform(get("/api/v1/users/{userId}/balance", 1L))
        .andExpect(status().isOk())
        .andExpect(jsonPath("$.data.amount").value(1_000_000L))
        .andDo(document("balance-get",
                pathParameters(
                        parameterWithName("userId").description("사용자 ID")
                ),
                relaxedResponseFields(
                        fieldWithPath("code").description("응답 코드"),
                        fieldWithPath("message").description("응답 메시지"),
                        fieldWithPath("data.amount").description("보유 잔액")
                )));
```

두 가지를 유의하여 작성하였다.

- **`RestDocumentationRequestBuilders`를 사용해야 한다.** 경로 변수를 문서화(`pathParameters`)하려면 요청 URI의 템플릿(`{userId}`)이 보존되어야 하는데, `MockMvcRequestBuilders`는 템플릿을 치환한 결과만 남긴다.
- **`relaxedResponseFields`를 사용하였다.** 공통 응답 래퍼(`ApiResponse`)는 데이터가 없는 API에서 `data`가 비어 있으므로, 모든 필드를 강제로 문서화하면 응답 형태에 따라 테스트가 실패한다.

## 스니펫 수집

멀티모듈 구조에서는 스니펫이 각 서비스의 `build/generated-snippets`에 흩어져 생성된다.  
반면 `docs/asciidoc/index.adoc`은 하나의 문서에서 7개 API를 모두 참조하므로, 스니펫을 한 디렉터리로 모으는 단계가 필요하다.

```groovy
def documentedProjects = ['balance', 'coupon', 'order', 'product'].collect { project(":service:$it") }

tasks.register('collectRestDocsSnippets', Sync) {
    dependsOn documentedProjects.collect { it.tasks.named('test') }

    from documentedProjects.collect { it.layout.buildDirectory.dir('generated-snippets') }
    into layout.buildDirectory.dir('generated-snippets')
}

asciidoctor {
    dependsOn tasks.named('collectRestDocsSnippets')
    configurations 'asciidoctorExt'

    sourceDir file('docs/asciidoc')
    sources { include 'index.adoc' }
    baseDirFollowsSourceFile()
    outputDir layout.buildDirectory.dir('docs/asciidoc')

    inputs.dir layout.buildDirectory.dir('generated-snippets')
    attributes 'snippets': layout.buildDirectory.dir('generated-snippets').get().asFile
}
```

`Sync`를 사용하여 이전 빌드에서 생성된 스니펫이 남지 않도록 하였다.  
삭제된 API의 스니펫이 문서에 계속 노출되는 것을 방지하기 위함이다.

## 버전 조합

Spring Boot 4.0.5는 Spring REST Docs 4.0.0을 관리하는데, 이 버전의 Asciidoctor 확장은 **AsciidoctorJ 3.x API로 컴파일되어 있다.**  
반면 Asciidoctor Gradle 플러그인 4.0.4는 AsciidoctorJ 2.x를 사용한다.  
두 조합을 그대로 사용하면 문서 변환 시점에 다음 예외가 발생한다.

```
java.lang.AbstractMethodError: Receiver class org.springframework.restdocs.asciidoctor.DefaultAttributesPreprocessor
does not define or inherit an implementation of the resolved method
'abstract void process(org.asciidoctor.ast.Document, org.asciidoctor.extension.PreprocessorReader)'
of abstract class org.asciidoctor.extension.Preprocessor.
```

AsciidoctorJ 3.x를 요구하는 플러그인 5.x 계열은 아직 정식 릴리스가 아니므로,  
**Asciidoctor 확장만 AsciidoctorJ 2.x 대응 버전(3.0.4)으로 고정**하는 방식으로 해결하였다.

```groovy
dependencies {
    asciidoctorExt 'org.springframework.restdocs:spring-restdocs-asciidoctor:3.0.4'
}
```

이 확장은 `operation::` 매크로와 `snippets` 속성만 제공하며 스니펫 파일을 읽어 조립하는 역할만 수행하므로,  
스니펫을 생성하는 `spring-restdocs-mockmvc` 4.0.0과 버전이 달라도 문제가 없다.

## 자동 배포

`main` 브랜치에 변경이 반영되면 문서를 생성하여 GitHub Pages로 배포한다.

```yaml
- name: REST Docs HTML 생성
  run: ./gradlew asciidoctor

- name: Pages 설정
  uses: actions/configure-pages@v5
  with:
    enablement: true

- name: 산출물 업로드
  uses: actions/upload-pages-artifact@v4
  with:
    path: build/docs/asciidoc
```

문서 생성 과정에 서비스 테스트 실행이 포함되므로, **테스트가 실패하면 배포가 중단된다.**  
문서가 갱신되었다는 것은 해당 시점의 API 테스트가 모두 통과하였다는 의미이다.

## 로컬 실행

```bash
./gradlew asciidoctor
```

`build/docs/asciidoc/index.html`이 생성된다.  
스니펫만 다시 만들려면 `./gradlew collectRestDocsSnippets`를 실행한다.
